Redesign Schedules as a cross-workflow automation schedule management
workspace. Use current behavior: list schedules, create/edit, enable/disable,
delete, view history, and open run/workflow links from history when available.

PLATFORM: Desktop web app screen.

PAGE STRUCTURE:
1. Header:
   - Eyebrow "Automation".
   - Page title "Schedules".
   - Summary chip: schedule count.
   - Primary action: New Schedule.
2. Schedule panel:
   - Dense table with status, schedule, workflow, next run, last result,
     actions.
   - Enabled and disabled states are visually distinct.
   - Focused schedule target row has clear selected treatment.
   - Last result shows status plus short reason.
3. Row actions:
   - Enable/Disable text button.
   - Edit icon.
   - History icon.
   - Delete destructive icon.
4. Create/Edit dialog:
   - Workflow select.
   - Name field.
   - Enabled switch.
   - Schedule kind control.
   - Kind-specific controls: once_at, interval with unit, daily time, weekly
     weekdays, monthly day.
   - Inline validation messages.
   - Footer: Save/Create primary, Cancel secondary.
5. History dialog or panel:
   - Schedule name and workflow.
   - Event list with created time, type/status, reason, run id when present.
   - Actions to open run/workflow when available.
6. Empty state:
   - "No schedules yet" with New Schedule action.

COMPACT DESKTOP:
- Table scrolls inside wrapper.
- Create/Edit dialog fits viewport with internal scroll.
- Weekday selector remains usable and does not overflow.

ACCEPTANCE CRITERIA:
- Schedule kind forms are grouped and easy to scan.
- Enabled/disabled and last-result states are not confused.
- History is readable and traceable.
