Redesign the Runs workspace for active and recent run monitoring. Use current
behavior: list run snapshots, show selected persisted run detail when provided,
show missing run target, stop active run, and open related Evidence, Workflow,
and Identity when links exist.

PLATFORM: Desktop web app screen.

PAGE STRUCTURE:
1. Header:
   - Eyebrow "Execution".
   - Page title "Runs".
   - Summary chips: active count and session run count.
2. Main panel:
   - Master-detail layout when a focused run detail exists.
   - Run table/list with workflow, source, status, step, started, issue, and
     actions.
   - Active rows show running status and scoped destructive Stop action.
3. Focused run detail:
   - Header with workflow name and status.
   - Run ID, started time, source, identity, issue summary.
   - Traceability actions: Open Evidence, Open Workflow, Open Identity.
   - Step timeline/list with step number, action type, status, error summary,
     artifact marker.
4. Missing run target:
   - Stale state with safe run id and return-to-list guidance.
5. States:
   - Empty: "No runs in this session".
   - Error: contained alert above panel.
   - Long issue text truncates in the table and expands in detail.

COMPACT DESKTOP:
- Table wrapper scrolls horizontally.
- Focused detail stacks above table.
- Hide issue text before hiding status/action.

ACCEPTANCE CRITERIA:
- Stop action is scoped to one run id.
- Run detail connects clearly to workflow/evidence/identity.
- Missing target state is explicit.
