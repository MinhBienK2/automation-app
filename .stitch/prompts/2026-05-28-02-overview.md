Redesign the Mission Control Overview workspace as the default operations
dashboard for authorized browser automation runs. Use the applied Mission
Control design system; do not add theme tokens or marketing styling.

PLATFORM: Desktop web app screen.

PAGE STRUCTURE:
1. Header:
   - Eyebrow "Operations Dashboard".
   - Page title "Overview".
   - Subtitle with local-day/timezone and last refreshed timestamp.
   - Actions: Refresh Overview and Open Workflows.
2. KPI row:
   - Active Runs.
   - Succeeded Today.
   - Attention Needed.
   - Upcoming Schedules.
   - Each metric has stable dimensions, value, label, context text, icon, and
     loading skeleton state.
3. Main grid:
   - Live Operations panel.
   - Attention Queue panel.
   - Execution Activity panel.
   - Recent Evidence panel.
   - Upcoming Schedules panel.
4. Live Operations:
   - Rows show workflow, identity, current step, elapsed time, source, and
     readable status.
5. Attention Queue:
   - Rows show severity, item type, workflow, short reason, status pill, and
     open-target action.
   - Focused Attention state includes a subtle focus chip/banner.
6. Execution Activity:
   - Compact timeline or bucket chart with legend for success, failed, blocked,
     and schedule attention.
7. Recent Evidence:
   - Artifact type, workflow, safe relative label, timestamp, and open evidence
     action.
8. Upcoming Schedules:
   - Schedule name, workflow, next run, last status, and open schedule action.

STATES:
- Loading: skeleton metric cards and stable row placeholders.
- Error: contained alert with Retry.
- Empty panels: quiet operational empty state with a short reason.

COMPACT DESKTOP:
- KPI cards become two columns.
- Main grid becomes one or two columns.
- Hide secondary row metadata before primary label/status/action.

ACCEPTANCE CRITERIA:
- Attention items are easier to scan than a plain list.
- Metrics do not jump during loading.
- Empty/error/loading states share one component language.
